# 07. 송도·독일 원자료의 구조를 이해한 뒤 분석 단위를 정하기

기록일: 2026-09-16. 대상: Songdo Traffic와 보유 독일 자료 5종 전체. 연구주제 확정이나 분석 구현이 아니라, 수집·가공·제공 구조의 확인 단계다.

**작성 이후 최신 지시:** 사용자가 불필요한 예비분석 노트북 삭제를 요청하여 01·02 노트북을 삭제했다. 아래의 노트북 보존 설명은 이 지시 이전의 경과이며 현재는 적용하지 않는다. 이 자료 구조 기록과 원자료는 보존한다.

## 왜 이 단계로 돌아왔는가

사용자는 처음부터 자료를 누가, 어디에서, 어떻게 수집했고 각 파일과 관측값이 무엇인지 파악하도록 요청했다. 그런데 자료 제작 논문과 배포 설명을 충분히 연결하기 전에 송도 시각 공백 점검을 진행했다. 문서에 이미 있는 수집·제공 구조를 먼저 설명했어야 한다. 두 예비분석 노트북은 사용자가 실행한 보조 확인 자료로 보존하고, 이 기록에서는 원자료 문서와 메타데이터를 기준으로 분석의 출발점을 다시 정리한다.

이번에 새로 확인한 것은 폴더·ZIP 내부 목록, 송도 README·지원 메타데이터·표본 CSV 헤더/첫 행, 독일 전체 recordingMeta와 CSV 헤더, 각 자료의 표본 행·지도 설명·변경 기록·공식 형식 문서·접근 가능한 제작 논문 및 정식 서지다. 거대한 tracks의 전체 행을 분석하거나, 상충·TTC/PET·EVT를 계산하거나, 원본을 수정하지 않았다. 과거 감사 JSON·구버전 분석 결과는 이번 수치의 근거로 사용하지 않았다.

사용자가 독일 연구팀에 요청해 받았다는 설명은 인지한다. ZIP만으로 개인별 신청·수령 경로나 허가 이메일을 확인할 수는 없으며, 개인 메일을 탐색하거나 외부에 연락하지 않았다.

폴더의 [Espadaler TRIP 논문](../references/TRIP_Espadaler2025/05_Espadaler_2025_안전혼잡모니터링_TRIP.pdf)은 Manchester 자료를 분석한 별도 연구다. 다만 사용자가 지적한 대로 **같은 EPFL 연구진의 연결된 연구**이며, Robert Fonod와 Nikolas Geroliminis는 TRIP 논문과 송도 제작 논문에 모두 참여했다. 송도 제작에는 KAIST의 Haechan Cho·Hwasoo Yeo가 함께 참여한다. 서로 무관한 팀이라는 의미로 구분하지 않는다. 두 원문 첫 페이지의 저자·소속을 대조했다. 송도 제작·배포 구조는 Fonod 논문을 직접 근거로 삼는다. uniD 전용 논문으로 언급된 ITSC 2021 원고의 정식 게재·DOI는 이번 확인에서 `not_found`다. 제출 중이라는 참고문헌을 게재 논문으로 바꾸어 기록하지 않는다.

## 2. 실제로 보유한 규모와 완전성의 의미

### 송도

`data/raw/`에는 날짜·교차로 조합 80폴더 × 10CSV = **800개 궤적 CSV**, 이에 대응하는 궤적 ZIP 80개와 지원 ZIP 3개가 있다.

| 지원 자료 | 실제 추출 폴더 내부 | 역할 |
|---|---|---|
| `orthophotos/orthophotos/` | PNG 20개, 교차로 중심 TXT 20개, 좌표변환 파라미터 TXT 1개 | 궤적을 올려 볼 지도 이미지와 좌표 연결 |
| `segmentations/segmentations/` | CSV 20개 | 도로 구역·차로별 다각형 |
| `master_frames/master_frames/` | PNG 20개, 변환 TXT 20개, CSV 2개, PDF 1개 | 기준 영상과 정사영상의 정합 정보, 기준 프레임 선정 자료 |
| README·LICENSE | 각 1개 | 파일·변수·알려진 제약·이용조건 |
| 샘플 영상 | 미보유 | 사용자가 의도적으로 받지 않은 자료. 궤적 ZIP 누락과 구분 |

`best_master_frames.csv`는 20행, `reference_frame_stats.csv`는 **3,100행**이다. 열은 지점, 영상 경로, 평균 위치·고도와의 거리, 객체 개수·화면 점유, 촬영 위치, 상대고도, 기준 프레임 등이다. 이 좌표는 차량 위치가 아니라 영상 기준 위치 관련 메타데이터다. `best_master_frames.pdf`는 20개 교차로의 정지 촬영 위치와 기준 프레임 선정 그림이다.

사용자는 필요할 경우 샘플 영상도 압축 해제하여 데이터 폴더에 함께 둘 수 있다고 허용했다. 후속 확인에서 현재 프로젝트의 압축파일 88개는 기존 송도 83개·독일 5개였고, `sample_videos.zip`이나 영상 파일은 발견되지 않았다. 다른 위치의 보유 여부는 확인하지 않았다. 공식 샘플은 2022-10-07 PM5의 정지 촬영 시작 60초 영상 29개로, 모든 날짜·사건을 확인할 전체 원영상은 아니다. 현재 자료 구조 대조에는 필수가 아니므로 다운로드·해제는 수행하지 않았다. 이후 해당 시점의 차량쌍·촬영 범위를 시각적으로 확인할 필요가 생기면, 보유 위치를 확인하고 원본을 보존한 채 `data/raw/sample_videos/` 아래에 정리한다.

### 독일 5종

아래 수치는 **이번에 각 ZIP 안의 모든 recordingMeta를 읽은 값**이다. 시간은 recording 길이를 합친 값이며, 객체 수는 제공된 메타 집계다. 국가 전체 차량 수, recording 간 중복을 제거한 실제 차량 수, 상충 사건 수가 아니다.

각 recording에는 `tracks.csv`, `tracksMeta.csv`, `recordingMeta.csv`, 배경 PNG가 모두 있다. 자료별로 이 네 파일군의 recording 번호 집합이 일치한다. 세 CSV의 개수는 각각 highD 180개, inD 99개, rounD 72개, exiD 279개, uniD 39개다. 독일 자료는 압축 상태로 보존되어 있다.

**완전성 판단의 범위:** 보유 파일군과 번호 구성은 확인했다. 공식 전체 원영상까지 보유했다는 뜻이 아니고, 공식 ZIP 체크섬·버전별 manifest와의 바이트 동일성이나 모든 궤적의 탐지 정확도를 이번에 검증한 것은 아니다. 과거 CRC·행 수 감사 결과를 이번 검사 완료로 대체하지 않는다. 독일 ZIP에는 원본 동영상이나 데이터셋 논문·형식 설명 PDF가 없으며, 설명 PDF는 공식 웹에서 대조했다.

## 3. 촬영시간·기록 단위·차량 시간의 구분

### 송도: 이동 촬영 후 구간을 통합한 세션 CSV

[Fonod 원문](../references/원논문_Fonod2025/04_Fonod_2025_송도데이터셋.pdf) p.2, p.6 §3.1, p.19 §3.7.3에서 다음을 확인했다.

1. 오전 5회·오후 5회, 비행 세션 약 30분과 배터리 교체를 포함한 40분 주기로 수집했다.
2. 한 비행에 정지 촬영·교차로 간 이동·이착륙이 포함된다.
3. 교차로 위에서 안정적으로 머문 구간을 잘라 궤적을 추출했다. 구간은 대체로 2–4분이며 드론·지점별로 다르다.
4. 3,000개 이상의 영상 구간별 CSV를 날짜·교차로·세션별 800개 CSV로 통합했다.

보유 `reference_frame_stats.csv`에도 `2022-10-04_A_AM1`에 해당하는 영상 경로 **D1/A1·D1/A2·D2/A1·D2/A2**가 있다. 한 CSV에 여러 드론·관측 구간이 합쳐질 수 있다는 직접적인 메타 근거다. 다만 이 표에는 각 구간의 실제 시작·종료시각 열이 없어, 예비분석에서 본 세 공백을 각 비행 이동과 일대일로 대응시킨 것은 아니다.

따라서 **약 30분 비행 세션, 해당 교차로를 관측한 구간들의 길이, 첫 차량부터 마지막 차량까지의 시각 차이**를 서로 구분한다. 정상적으로 촬영했지만 차량이 없는 시간은 관측시간에 포함할 수 있다. 시간 공백만 보고 촬영 실패나 무교통 상태를 확정하지 않는다.

### 독일: recording과 track을 별도 파일로 설명

공식 형식 문서는 recording의 길이를 `recordingMeta.duration`(초)으로 제공하고, 개별 객체의 등장·퇴장을 `tracksMeta.initialFrame/finalFrame/numFrames`로 구분한다. inD·rounD·uniD 형식 p.1은 지점 자료를 연속 recording으로 나눈다고 명시한다. highD 원논문 p.5도 recording 사이 배터리 교체를 설명한다.

- 기록 길이는 **제공 duration에서 먼저 확인**한다. 차량이 없는 시간을 임의로 빼거나 차량별 체류시간을 합해 대체하지 않는다.
- 같은 recording에서 두 관측의 시간차는 `프레임 차이 / frameRate`다. 5종의 메타 frameRate는 모두 25다.
- `trackLifetime`은 객체별 경과 프레임이지 서로 다른 객체의 공통 시각이 아니다.
- recording 여러 개의 duration 합은 그 시간만큼 한 번에 연속 촬영했다는 뜻이 아니다.
- highD의 `totalDrivenTime`은 차량별 주행시간의 합으로, 촬영시간인 `duration`과 다르다.
- highD는 월·연도 및 시:분 형식 시작시각을 제공하지만 정확한 날짜·초까지 제공하지 않는다. inD·rounD·uniD의 `startTime`은 시(hour) 단위다. inD 07–10은 빈칸, exiD 93개 recording은 모두 빈칸이다. 정밀한 실제 날짜·시각을 지어내어 recording을 이어 붙이지 않는다.
- 프레임 개수와 첫·마지막 시점의 차이는 한 프레임만큼 다를 수 있다. duration과 실제 전체 프레임 경계의 일치까지 이번에 새로 검증한 것은 아니다.

근거: 공식 [highD 형식](https://levelxdata.com/wp-content/uploads/2023/10/highD-Format.pdf), [inD 형식](https://levelxdata.com/wp-content/uploads/2024/03/inD-Format_1_1.pdf), [rounD 형식](https://levelxdata.com/wp-content/uploads/2024/03/rounD-Format.pdf), [exiD 형식](https://levelxdata.com/wp-content/uploads/2023/10/exiD-Format.pdf), [uniD 형식](https://levelxdata.com/wp-content/uploads/2024/03/uniD-Format-1_1.pdf)과 로컬 메타데이터.

## 4. 파일 하나·행 하나·변수의 뜻

### 송도 17개 열

한 행은 **특정 시각에 특정 차량이 관측된 궤적 점**이다. 같은 차량의 행들을 시간순으로 모으면 궤적이 되고, 상충 사건은 두 차량 이상과 별도 사건 정의가 있어야 구성된다.

| 열 | 뜻·단위 | 분석 전에 기억할 사항 |
|---|---|---|
| `Vehicle_ID` | CSV 내부 차량 식별자 | 다른 CSV의 같은 번호를 동일 차량으로 연결하지 않음. 분절·드론 중복으로 실제 차량과 일대일이 아닐 수 있음 |
| `Local_Time` | 한국 현지시각 `hh:mm:ss.sss` | 날짜는 파일명에 있음 |
| `Drone_ID` | 촬영 드론 번호 | 세션 CSV 내부에 여러 드론이 포함될 수 있음 |
| `Ortho_X`, `Ortho_Y` | 정사영상에서 차량 중심, pixel | 해당 8000×8000 정사영상과 연결 |
| `Local_X`, `Local_Y` | EPSG:5186 평면 중심좌표, m | 거리 계산용 위치. 영상 pixel과 혼용하지 않음 |
| `Latitude`, `Longitude` | WGS84 위치, degree | 미터 좌표와 다름 |
| `Vehicle_Length`, `Vehicle_Width` | 추정 길이·폭, m | 결측 가능. 빈 값을 크기 0으로 바꾸지 않음 |
| `Vehicle_Class` | 0 자동차·밴, 1 버스, 2 트럭, 3 오토바이 | 일반 보행자·자전거 궤적까지 포함한 자료로 취급하지 않음 |
| `Vehicle_Speed` | 추정 속력, km/h | 방향을 갖는 속도벡터가 아님 |
| `Vehicle_Acceleration` | 추정 가속도, m/s² | 센서 실측이나 x/y 가속도벡터로 간주하지 않음 |
| `Road_Section`, `Lane_Number` | 도로 구역·차로 | 중앙 교차영역 등에는 라벨이 없을 수 있음 |
| `Visibility` | 화면에서 완전히 보임 1, 일부만 보임 0 | 신호상태나 탐지오차 없음의 보증이 아님 |

README와 Fonod p.18 §3.7.2는 제공 속력·가속도가 보간과 평활을 거친 추정치라고 설명한다. 저자는 주로 운동상태 기반 검색을 돕기 위한 값이며 상세 교통 분석의 확정적 운동 프로파일을 의미하지 않는다고 명시한다. 지리참조 궤적 좌표 자체를 이 속력 처리와 동일하게 평활된 값이라고 설명하지 않는다. 위치로부터 TTC용 방향·속도벡터를 어떻게 구성할지는 이후 방법론 결정이다.

### 독일의 CSV 세 종류

| 파일 | 한 행의 뜻 | 대표 정보 |
|---|---|---|
| `tracks.csv` | 한 객체의 한 프레임 상태 | 위치·크기·운동 상태. 데이터셋에 따라 차로·이웃차 정보 |
| `tracksMeta.csv` | 한 track의 요약 | ID, 처음·마지막 프레임, 프레임 수, 차종·크기 |
| `recordingMeta.csv` | 한 recording의 설명 | 지점, frameRate, duration, 시작시각, 객체 수, 좌표 원점 등 |

객체 식별에는 최소 **데이터셋 + recording 번호 + track ID**가 필요하다. highD는 recording 번호가 파일명에 있고 `id` 열을 쓰며, 나머지는 `recordingId/trackId`를 쓴다. 숫자 ID만 같다고 다른 recording·자료 사이 같은 차량은 아니다.

### 좌표와 단위는 독일 자료끼리도 다름

| 항목 | highD | inD·rounD·uniD 및 exiD |
|---|---|---|
| 위치 | `x,y`: 박스 왼쪽 위 모서리 | `xCenter,yCenter`: 객체 중심 |
| 축 방향 | x 오른쪽, y 아래쪽 | x 오른쪽, y 위쪽 |
| 크기 이름 | `width`=차량 길이에 대응, `height`=차량 폭에 대응 | `length`=길이, `width`=폭 |
| 속도·가속도 | x/y 성분, m/s·m/s² | x/y 및 차량 종/횡방향 성분, m/s·m/s² |
| 방향 | heading 열 없음 | heading 열 있음, degree |
| 지도 좌표 | 영상에 맞춘 지역 좌표 | 지역 UTM 중심좌표와 UTM 원점 정보 |

`lonVelocity/latVelocity`는 **종방향·횡방향 속도**이며 경도·위도 변화량이 아니다. 송도 km/h와 독일 m/s를 통일해야 한다. heading의 정확한 0도와 회전방향은 구현 전에 해당 공식 도식·도구와 대조할 항목으로 남긴다.

inD·rounD·uniD 실제 tracks의 공통 17열은 다음과 같다.

```text
recordingId,trackId,frame,trackLifetime,xCenter,yCenter,heading,width,length,
xVelocity,yVelocity,xAcceleration,yAcceleration,
lonVelocity,latVelocity,lonAcceleration,latAcceleration
```

이들에는 차량쌍 ID·선행차 ID·laneId·TTC·PET 열이 없다. exiD는 이 17열에 지도·주변 차량 관련 변수를 더한 구조다.

나머지 제공 변수도 다음처럼 역할을 구분한다. 상세 계산 정의는 해당 판본 공식 형식 문서를 따른다.

| 변수 묶음 | 뜻 |
|---|---|
| `frameRate`, `duration`, `startTime`, `weekday/weekDay`, `month` | 촬영 단위의 시간 정보. startTime의 정밀도·결측은 자료별로 다름 |
| `numTracks`, `numVehicles`, `numVRUs`, `numCars`, `numTrucks` | recording 안의 객체 구성 집계. 전 자료에 동일하게 존재하지 않음 |
| `latLocation/lonLocation`, `xUtmOrigin/yUtmOrigin`, `orthoPxToMeter` | 촬영 지점, 지역 좌표 원점, 배경영상 pixel–m 연결. 개별 차량의 위경도가 아님 |
| `speedLimit` | 메타데이터의 제한속도. 개별 차량의 속도가 아님 |
| `initialFrame/finalFrame/numFrames`, `class` | 개별 track의 등장·퇴장·기록 수·분류 |
| highD `frontSightDistance/backSightDistance` | 차량 중심에서 촬영된 도로 구간의 끝까지 진행방향·반대방향으로 잰 거리(m). 운전자 시야나 선행차 간격이 아님 |
| highD `drivingDirection`, `upperLaneMarkings/lowerLaneMarkings` | 진행방향과 상·하행 차로 경계 |
| `traveledDistance`, `totalDrivenDistance/Time`, `min/max/meanXVelocity`, `minDHW/THW/TTC`, `numLaneChanges` | highD tracksMeta의 traveledDistance는 track 전체 이동거리, exiD tracks의 같은 이름은 해당 프레임까지 누적 이동거리. total은 recording의 차량 합계, min/max 등은 track 요약 |
| exiD `latLaneCenterOffset/laneWidth`, `laneletId`, `laneChange`, `lonLaneletPos/laneletLength` | 차로 중심과의 거리, 차로 폭, 지도 구간 ID, 차로 변경, 차로 구간 내 종방향 위치·길이 |
| DHW·THW·TTC·DV 및 주변 차량 ID | 앞차와의 거리·시간 간격·예상 충돌시간·상대속도 및 관계. 부재값과 적용 차량쌍 정의 확인 필요 |

로컬 실제 헤더를 기준으로 inD·rounD·uniD의 tracksMeta는 다음과 같다. exiD도 같은 열 구성을 갖는다.

```text
recordingId,trackId,initialFrame,finalFrame,numFrames,width,length,class
```

inD·rounD·uniD의 recordingMeta 실제 헤더는 다음과 같으며 exiD에는 마지막에 `exportVersion`이 더 있다.

```text
recordingId,locationId,frameRate,speedLimit,weekday,startTime,duration,
numTracks,numVehicles,numVRUs,latLocation,lonLocation,xUtmOrigin,yUtmOrigin,orthoPxToMeter
```

highD는 같은 형식이라고 가정하지 않는다. 실제 헤더는 아래와 같다.

```text
tracks:
frame,id,x,y,width,height,xVelocity,yVelocity,xAcceleration,yAcceleration,
frontSightDistance,backSightDistance,dhw,thw,ttc,precedingXVelocity,
precedingId,followingId,leftPrecedingId,leftAlongsideId,leftFollowingId,
rightPrecedingId,rightAlongsideId,rightFollowingId,laneId

tracksMeta:
id,width,height,initialFrame,finalFrame,numFrames,class,drivingDirection,
traveledDistance,minXVelocity,maxXVelocity,meanXVelocity,minDHW,minTHW,minTTC,numLaneChanges

recordingMeta:
id,frameRate,locationId,speedLimit,month,weekDay,startTime,duration,
totalDrivenDistance,totalDrivenTime,numVehicles,numCars,numTrucks,upperLaneMarkings,lowerLaneMarkings
```

exiD tracks의 실제 헤더는 다음과 같다.

```text
recordingId,trackId,frame,trackLifetime,xCenter,yCenter,heading,width,length,
xVelocity,yVelocity,xAcceleration,yAcceleration,lonVelocity,latVelocity,lonAcceleration,latAcceleration,
traveledDistance,latLaneCenterOffset,laneWidth,laneletId,laneChange,lonLaneletPos,laneletLength,
leadDHW,leadDV,leadTHW,leadTTC,leadId,rearId,leftLeadId,leftRearId,leftAlongsideId,
rightLeadId,rightRearId,rightAlongsideId
```

## 5. 지도와 교통상황을 구분해야 하는 이유

| 자료 | 보유 지도·환경 | 이번에 확인한 차이 |
|---|---|---|
| 송도 | 교차로 정사영상·차로 다각형·기준 영상과 변환 | 차로 밖 중앙영역의 무라벨이 곧 궤적 오류는 아님. 신호현시 시계열 없음 |
| highD | recording별 배경 PNG·메타 차로 경계 | 해당 ZIP에는 Lanelet2/OpenDRIVE 없음. 본선 주행·차로 변경 자료 |
| inD | 4지점과 공사판본의 Lanelet2·OpenDRIVE·3D 자료 | 4곳 모두 비신호 교차로. Bendplatz 11–17 recording에는 공사판본 지도를 써야 함 |
| rounD | 3지점의 Lanelet2·OpenDRIVE·3D 자료 | 회전교차로. 3곳의 관측량이 균등하지 않음 |
| exiD | 7지점의 Lanelet2·OpenDRIVE·3D 자료 | 고속도로 진입·진출부. v2.1에서 지도·객체 크기 보정 등의 변경 |
| uniD | SuperC 한 지점의 Lanelet2·OpenDRIVE·3D 자료 | 대학 앞 공유공간·차량/VRU 상호작용. 지도에 신호등 규제 요소가 있지만 신호상태 시계열은 없음 |

지도에서 도로 구조나 규제 요소를 확인할 수 있다는 사실과, 특정 순간 신호가 무엇이었는지는 다르다. uniD를 단순히 무신호 교차로나 송도와 같은 신호교차로라고 단정하지 않는다.

inD 지점은 location 1 Bendplatz(07–17, 11개), 2 Frankenburg(18–29, 12개), 3 Heckstrasse(30–32, 3개), 4 ASEAG/Neuköllner Strasse(00–06, 7개)다. 두 곳은 4지, 두 곳은 T자이며 우선통행 조건도 다르다. 원논문 p.5와 지도 README를 근거로 한다. 공사판본 폴더의 실제 철자는 `01_bendplatz_constuction`이며 `location1_construction.osm`이 있다.

rounD는 location 0 Neuweiler에 recording 02–23의 **22개**, location 1 Kackertstrasse에 00 **1개**, location 2 Thiergarten에 01 **1개**다. 세 지점에서 같은 시간·같은 양을 확보했다고 전제하면 안 된다.

송도 정사영상의 `Ortho_X/Y`는 8000픽셀 영상 기준이다. 공식 v2 배포 설명은 `*_center.txt`와 원본 pixel scale이 15000픽셀 cut-out 기준이므로 지리좌표를 재계산할 경우 축척을 반영해야 한다고 설명한다. 이미 제공된 Local_X/Y를 쓸 때 이 변환을 불필요하게 다시 수행하지 않는다. lane polygon은 Ortho_X/Y와 같은 8000픽셀 공간이다.

## 6. 이미 계산되어 있는 안전 지표도 그대로 합치면 안 됨

| 자료 | 기존 안전·차량쌍 관련 열 | 의미와 제약 |
|---|---|---|
| 송도 | 없음 | 차량쌍·사건·TTC/PET를 정의해야 함 |
| inD·rounD·uniD | 없음 | 중심위치·heading·속도벡터·지도를 활용할 수 있지만 상충표가 이미 있는 것은 아님 |
| highD | DHW, THW, TTC, 선행·후행·좌우 차량 ID, laneId | 고속도로 선행차 관계의 지표. `ttc=0`은 유효 TTC/선행차 없음 표시이며 충돌 0초로 해석하면 안 됨. tracksMeta `minTTC=-1`도 유효값 없음 |
| exiD | leadDHW/DV/THW/TTC, 앞뒤·좌우 ID, laneletId 등 | leadTTC/THW/DHW의 -1, leadDV의 -1000, 이웃 ID의 -1은 부재 기본값. 옆 차량 ID 필드는 비어 있거나 여러 ID일 수 있음 |

6종 모두 제공 열에 PET나 M1/M2와 동일하게 구성된 사건별 TTC/PET 쌍, 상충 사건 정답, 대응 사고기록이 없다. highD·exiD의 선행차 TTC를 좌회전–직진 crossing TTC로 바꾸어 부르지 않는다. 결측·부재 표시는 유효값으로 처리하거나 부호 반전해 EVT 극단표본에 넣으면 안 된다.

## 7. 문서·버전 차이와 아직 확정하지 않은 내용

| 항목 | 확인된 차이·한계 | 처리 원칙 |
|---|---|---|
| Songdo 객체 수 | 논문은 688,840 궤적. ID 분절·드론 중복 가능성을 별도로 설명 | 고유 실제 차량 수라고 일반화하지 않음 |
| Songdo 구간 메타 | reference_frame_stats에 경로·촬영 위치 등이 있지만 구간 시작·종료시각 열 없음 | CSV 시각 공백을 비행 기록의 정확한 대체물로 사용하지 않음 |
| inD 초기 논문과 v1.1 | 2019 원고의 약 11,500은 초기 설명, 보유 메타는 13,599 tracks | 본 연구 자료 규모는 보유 버전 메타로 명시 |
| VRU 크기 | inD/rounD/uniD 공식 형식은 VRU 크기 0을 설명. 그러나 rounD00 첫 pedestrian 행은 width 0.8158, length 1.0443 | 문서 규칙을 적용해 실제 값을 덮어쓰지 않음. 0도 물리적 크기 0으로 해석하지 않음 |
| length 설명 | 일부 형식 문서의 tracks 설명은 height라고 쓰지만 tracksMeta·평면 크기 맥락은 length | 차량 높이 변수로 바꾸지 않음 |
| exiD 버전 | 보유 ZIP v2.1과 `exportVersion=1.0`은 서로 다른 버전 정보 | 동일 개념으로 비교하지 않음 |
| exiD 열 | 형식 문서의 odrRoadId/odrSectionNo/odrLaneId는 실제 보유 헤더에 없음 | 실제 헤더 기준으로 가능 여부 판단 |
| highD 배경 | 형식 문서는 JPG, 실제 보유 파일은 PNG | 실제 파일명 사용 |
| highD 차량시간 | 웹 147 driven hours, 원논문 447, 로컬 메타 totalDrivenTime 합 약 440.17 차량·시간으로 차이 | 원인 미확정. 어느 것도 duration 약 16.66시간과 혼동하지 않음 |
| 원문 접근 범위 | rounD·exiD 정식 서지와 공식 설명·형식은 확인. 이번에는 정식 논문 전문 전체 미확보 | 세부 추출 알고리즘을 원문 확인 사실로 쓰지 않음 |
| 오류·극단표본 충분성 | 구조·메타 검토만 수행 | 객체 수가 많다는 이유로 유효 상충·꼬리 표본이 충분하다고 결론내리지 않음 |

과거에 기록된 exiD finalFrame 불일치 문제는 이번 구조 검토에서 재검증하지 않았다. 원본을 수정하지 않으며 후속 구현 시 확인할 기존 주의사항으로만 둔다.

이용조건도 다르다. 송도는 CC BY 4.0이다. 독일 자료는 동봉 LICENSE가 있는 경우 해당 파일과 공식 배포 페이지에서 비상업 연구·인용·원자료 재배포 제한을 확인했다. highD ZIP에는 별도 LICENSE가 없어 [공식 페이지](https://levelxdata.com/highd-dataset/)를 근거로 삼았다. 공식 자료 접근 창구와 이용조건을 기록한 것이며, 개인별 신청 권한을 새로 판정하거나 외부에 문의한 것은 아니다.

## 8. 현재 연구 방향에 연결되는 판단

**송도를 중심으로 교통상충 TTC/PET·단변량/이변량 EVT를 검토한다는 큰 방향은 유지한다.** 모든 자료를 확보했다는 이유로 서로 다른 상황을 한 표본에 합치지 않는다.

| 다음에 대조할 질문 | 자료에서 이미 아는 것 | 아직 정할 것 |
|---|---|---|
| 같은 순간의 두 차량을 구성할 수 있는가 | 송도 Local_Time, 독일 recording/frame 제공 | 관측 구간·드론 중복·차량 ID 및 후보쌍 규칙 |
| M1의 교차 경로 TTC/PET를 구성할 수 있는가 | 위치·지도 있음. 독일 일부는 heading·속도벡터도 있음 | 대상 이동류, 차량 경계, 예측 운동 가정, 통과시각·사건 대표값 |
| 두 자료의 사건이 같은 의미인가 | inD는 비신호 교차로, rounD는 회전교차로, highD/exiD는 고속도로, uniD는 대학 앞 공간 | 송도에서 선택한 사건과 독일 사건의 도로·우선통행·이동류 비교 범위 |
| 사고빈도 검증을 할 수 있는가 | 원자료 묶음에는 대응 사고기록 없음 | 실제 검증 목표·외부 사고자료 필요성과 확보 가능성 |

다음 작업은 이 변수·관측 단위와 **M1/M2의 사건 정의를 항목별로 대조**하는 것이다. 그 결과 필요한 입력이 무엇인지 정해진 뒤에만 최소 예비분석이나 새 노트북을 설계한다. 시간 길이·순위·국가 비교 자체를 연구주제로 바꾸지 않으며, 이 기록으로 최종 연구질문이나 차별성을 확정하지 않는다.
