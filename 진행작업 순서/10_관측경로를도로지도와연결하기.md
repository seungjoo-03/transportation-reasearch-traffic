# 10. 관측된 경로를 도로 지도와 연결하기

기록일: 2026-09-16. 최신 상태: **사용자가 02 전체 실행·저장을 완료했고, 저장된 전수 경로 집계와 지도 출력을 검토함**. 아래 실행 전 검증 경과와 마지막 실제 실행 결과를 구분한다. 확정된 이동류·차량쌍·TTC/PET 결과는 아직 없다.

## 01의 결과에서 왜 이 단계로 넘어가는가

01에서 송도 전체 800개 파일을 처리하여 차량별 관측 기록과 도로·차로 번호가 이어진 묶음을 만들었다. 사용자가 저장한 실행 `20260916T063821Z_28f9e8ee`는 688,840개 궤적 기록과 776,944,506개 관측행을 포함한다. 사용자와 관측행·궤적·라벨 묶음의 의미를 확인한 뒤 다음 작업을 요청받았다.

이제 필요한 것은 **그 번호가 지도에서 어느 도로를 가리키고, 차량이 어떤 구역을 어떤 순서로 거쳤는가**다. 이를 알아야 M1의 교차 경로 차량 관계와 M2의 같은 접근 차로 내 앞뒤 차량 관계를 우리 자료에서 구성할 수 있다. 촬영 회차나 제작팀을 다시 조사하는 단계가 아니다.

예를 들어 01의 차량 1번은 `3_1` 안에서 차로 번호가 여러 번 바뀌다가 `3_2`가 기록돼 총 8개 라벨 묶음이 생겼다. **도로 구역만 보는 수준에서는 `3_1 → 3_2`라는 관측 순서로 요약**할 수 있다. 이것은 차로 변화를 오류라고 지우거나 궤적을 평활하는 것이 아니다. 원래 차로 순서와 모든 원자료는 그대로 두고, 도로 구역을 살펴보기 위한 별도의 요약을 만든다.

**번호만으로 확인되지 않은 것:** `G=1`은 진입, `G=2`는 진출이라는 규칙, 특정 N/G의 동서남북 대응, 다각형 모서리 순서와 차량 진행 방향의 대응, 구역 번호 쌍에서 좌회전·직진·우회전으로 바꾸는 표는 이번에 대조한 원문에서 not_found다. 첫·마지막 관측점이 교차로 진입·진출점이라는 보장도 없다. 이를 임의 규칙으로 채우지 않는다.

파일명의 A/B 등은 지점 식별자이고, `N_G`는 그 지도에서 사용되는 구역 식별 구조다. 두 식별자를 같은 의미로 읽지 않는다. 예를 들어 `3_1`과 `3_2`는 N은 같고 G가 다른 두 section이다. 지도에서 실제 위치를 확인하기 전 이를 방향 이름으로 번역하지 않는다.

Fonod p.15 Fig.9의 단일 교차로 cut-out 예시에도 N=1,2,3,4인 여러 section이 함께 표시돼 있다. 따라서 N이 바뀌었다는 이유만으로 파일의 A/B 지점이 바뀌었다고 해석하지 않는다. N을 진입 방향 번호로 번역하는 것은 별도의 지도 대조 없이 확정하지 않는다.

## 02가 만드는 자료와 해석

대상 노트북: [02_송도_도로구역경로와지도연결.ipynb](../analysis/02_송도_도로구역경로와지도연결.ipynb).

1. 사용자가 완료한 **현재 01 실행**을 명시적으로 지정한다. 다른 실행을 자동 선택하거나 삭제한 과거 노트북·출력을 복원하지 않는다.
2. 전체 800개 궤적 요약을 읽어, 각 차량에서 도로 구역이 연이어 같을 때만 하나로 요약한다. `A → 무라벨 → A`는 세 부분을 그대로 남긴다. 여기의 A는 설명용 구역 기호다.
3. 지점과 관측 구역 순서가 같은 궤적을 경로 목록으로 정리한다. 각 경로에 속한 모든 차량의 파일·ID와 원래 품질 집계를 보존한다. 한 구역에서만 관측된 차량도 제외하지 않는다.
4. 제공된 20지점 도로·차로 지도를 연결하고, 지도에 없는 구역 번호와 무라벨을 구분한다. 번호만으로 이동 방향을 자동 확정하지 않는다.
5. 전체 경로 목록에서 확인할 경로·차량을 선택하면 실제 관측점을 지도에 표시한다. 이때만 해당 원자료 CSV를 읽는다. 화면 표시를 위해 고르는 사례는 전체 분석 범위를 줄이는 표본선정이 아니다.

경로 목록의 처음·마지막 구역은 **처음·마지막으로 관측된 구역**이다. 이를 진입·진출 구역이나 완전한 통과 경로로 바꿔 부르지 않는다. 공백을 넘는 선을 그리거나 무라벨 구간을 채워 관측되지 않은 이동을 만드는 것도 피한다.

전체 경로 수·빈도는 관측 자료의 구성이다. 경로 빈도가 많다는 사실을 위험도가 높다는 뜻으로 읽지 않는다. 상충 건수, 실제 차로 변경 건수, TTC/PET, EVT 적합 결과는 02의 산출물이 아니다.

## 실행·보존 원칙

- 분석 코드는 `.ipynb`로 작성하며 실제 자료 분석은 사용자가 실행한다.
- 원본 CSV·지도·ZIP과 사용자가 저장한 01 노트북 및 01 결과는 읽기 전용 입력이다.
- 전체 경로 집계에는 01의 요약을 사용하므로 원자료 80GB를 다시 전수 처리하지 않는다. 선택 차량을 지도와 대조할 때는 해당 원자료를 읽는다.
- 결과는 `data/processed/songdo_routes/`의 실행별 새 폴더에 저장하고 입력 실행·파일 출처를 기록한다.
- 일부 파일만 처리되거나 중단되면 전체 완료로 표시하지 않는다. 처리 범위와 오류를 함께 남긴다.

## 작성 후 검토한 범위

문헌 검토자와 코드 검토자를 분리했다. 문헌 검토에서는 위 원문 연결과 M2의 대상 범위를 확인했다. 코드 검토에서는 **29개 전체 셀·14개 코드 셀의 구조와 문법, 고유 셀 ID, 빈 출력·미실행 상태**를 확인했다.

작은 메모리 입력으로 구역 순서 함수의 동작을 확인했다. 차로 변화만 있는 경우의 구역 요약, 무라벨을 사이에 둔 같은 구역의 재등장, 한 구역·무라벨만 있는 기록·유효 시각 없는 빈 순서의 보존, 출처·품질 필드 보존을 검증했다. 실제 송도 자료를 이 테스트의 결과로 대체하지 않았다.

파일을 실제로 읽고 쓰는 부분을 메모리 입출력으로 대체한 코드 시험에서는 완료·일부 실패·첫 파일 중단·전체 실패 상태를 구분하는지, 완료 파일만 집계하는지, 새 결과 폴더 밖 쓰기를 거부하는지 확인했다. 선택 차량 표시 코드의 원래 행 번호·밀리초 시각·중복 시각·좌표 오류 처리와 지도 축척도 검토했다.

독립 검토에서 **부분 실패가 섞인 진행표의 숫자를 다시 읽을 때 문자열 소수 형태가 되어 집계가 중단될 수 있는 문제**를 재현했다. 완료 행의 집계 값을 명시적으로 숫자로 변환하도록 고쳤다. 실패 행과 섞일 때 나노초 수정 시각의 정밀도가 손실되지 않도록 출처 기록도 수정하고 재검증했다. 최종 검토는 사용자 실행 준비 범위에서 PASS, 차단 사항 0이다.

이 검토는 **코드와 처리 규칙의 검증**이다. 실제 800개 요약의 02 변환, 실제 지도의 결과 검토 또는 차량쌍 분석을 실행한 것은 아니다. 사용자가 저장한 01 노트북의 SHA-256도 작업 전후 일치함을 확인했다. 02 실행 후의 실제 경로 집계와 지도 해석은 별도로 확인한다.

## 실행 결과를 확인한 뒤의 다음 연결

02 결과에서 관측된 경로와 지도상 도로의 대응을 확인한 뒤, 같은 접근 차로에서 앞뒤로 이어지는 차량과 교차 경로 차량을 구분하는 구체적 사건 구성 규칙으로 넘어간다. M2의 후미추돌 후보를 만들기 위해 모든 차량의 최종 좌·우회전까지 반드시 분류해야 한다는 조건은 추가하지 않는다.

중복 시각의 원인·처리, 송도의 방향·속도벡터 구성, PET의 공간/선 정의, 사건 분리는 여전히 별도 근거가 필요한 항목이다. 경로를 정리했다는 이유로 이 문제들까지 해결됐다고 기록하지 않는다. 연구 주제는 교통상충 TTC/PET 단변량·이변량 EVT라는 현재 큰 틀을 유지한다.

## 사용자 실행 후: 전수 집계와 A 상세 화면을 구분

사용자는 02 실행·저장 후 결과 설명과 “20개를 모두 봐야 하는데 왜 A만 보이는가”를 질문했다. 저장 노트북의 마지막 출력은 실행 `20260916T084027Z_f3ab95c0`을 가리킨다. 앞선 두 실행 폴더와 합치지 않고 이 실행만 검토했다. 원자료나 노트북을 재실행하지 않았다.

| 항목 | 저장 결과 | 해석 |

| 도로·차로 지도 | 개별 20장 + 모아보기 1장 | 지도 경계·라벨 그림이며 모든 차량 궤적을 겹친 그림은 아님 |
| 상세 차량 관측점 | A의 차량 109, 387행 | 기본값으로 선택한 한 차량. 모든 지점의 실제 이동경로를 검증한 것은 아님 |

9번 셀의 전체 경로 표는 지점·빈도순 정렬 후 `.head(20)`으로 표시하므로 앞부분 A의 행만 화면에 나타났다. 11번 셀의 `SELECT_SITE="A"`와 나머지 `None` 기본값은 A의 최다 빈도 구역 순서와 그 목록의 첫 차량을 선택한다. 이 두 표시 방식이 A만 분석한 것처럼 보이게 할 수 있다. 전체 카탈로그와 지점별 집계는 20지점을 포함한다.

독립 검토에서는 입력·진행·출처 표 각 800개, 경로 목록 7,228개와 지점별 집계의 합계를 대조했다. 01의 제어 파일 3개와 궤적 요약 800개의 현재 SHA-256이 02에 기록된 값과 모두 일치했다. 이는 저장 결과와 입력 출처의 정합성 확인이며 원자료 전체의 재분석이 아니다.

### 구역 번호의 유무와 선택 차량 결과

### 실제 출력에서 추가로 확인한 표시 문제와 다음 확인 대상

**E·R 지도의 차로 도형 일부가 생략됐다.** 전체 1,339개 도형 중 E 10개, R 17개가 현재 코드의 `polygon_valid` 조건을 충족하지 않았다. 저장된 `map_index.csv`를 확인하니 27개 모두 좌표는 유한한 숫자이고, E의 `3_2/3_3` 도형은 일부 좌표가 최대 8,332, R의 `1_7/1_1/4_7/4_1` 도형은 일부 좌표가 최소 −104다. 현재 코드는 꼭짓점 하나라도 0~8000 범위 밖이면 도형 전체를 그리지 않는다. **이것은 지도 표시 조건의 문제이며 차량 궤적 삭제나 원자료 손상을 확인한 결과가 아니다.** 화면 안에 걸치는 부분을 표시할 수 있도록 보완해야 한다. 현재 검토에서는 사용자가 저장한 코드·출력·원자료를 수정하지 않았다.

**중복 시각 행은 H에 집중돼 있다.** 전체 406,320행 중 H가 404,416행(99.53%)이다. 이는 같은 파일·같은 차량 ID의 시각 중복 묶음에 속한 모든 행의 수이며, 중복 차량 수나 삭제해야 하는 초과 행 수가 아니다. 원인은 이 집계만으로 확정하지 않는다.

전수 경로 집계가 끝났다는 것과 모든 지점의 실제 경로를 해석했다는 것은 다르다. **20지점 모두의 지도·관측 경로를 검토하는 범위는 유지**한다. 단순히 지점마다 차량 한 대씩 보는 것으로 전체를 검증했다고 하지 않으며, 지점별 분석 대상 경로·접근 차로와 실제 관측을 연결해야 한다. A는 화면 확인용 기본 예시일 뿐 연구 대상 지점을 A로 줄인 것이 아니다.

### 저장 지도 20개 직접 열람

`map_atlas/`의 A·B·C·E·F·G·H·I·J·K·L·M·N·O·P·Q·R·S·T·U 개별 PNG를 모두 열어 구역·차로선과 라벨 표시를 확인했다. 다차로와 짧은 인접 구역에서 숫자가 겹치거나 가장자리 글자가 잘리는 부분이 있어, 모든 라벨이 이 축척에서 완전히 읽힌다고 주장하지 않는다. 색상은 반복되므로 구역 식별은 색만이 아니라 번호로 해야 한다.

R 지도 우하단에는 흰 정사영상 배경 위로도 일부 구역 다각형이 뻗어 있다. 이는 위의 꼭짓점 범위 검사와 별도로, 지도에서 실제 영상이 있는 범위와 도형 범위를 대조할 사항이다. 정적 그림만으로 해당 구역의 차량 관측 유무·손실·상충을 판정하지 않는다. 이번 열람은 지도 표시 확인이며, 20지점의 모든 차량 경로를 실제 관측점과 대조한 검증을 대신하지 않는다.

## 다음 진행: 전체 관측점을 경로 목록에 연결하는 03 준비

사용자는 20지점 전체를 대상으로 다음 작업을 진행하도록 요청했다. 이에 새 `03_송도_20개지점_실제경로대조.ipynb`를 준비한다. 사용자가 실행·저장한 01과 02의 코드·출력은 보존한다. 02 집계를 다시 만드는 것이 아니라, 고정된 02 실행 `20260916T084027Z_f3ab95c0`의 차량–경로 연결에 **원자료의 실제 관측 위치**를 붙인다.

### 이번 연결로 확인할 것

02의 `3_4 → 무라벨 → 4_3` 같은 순서만으로는 차량이 그 사이 어디를 지나갔는지 알 수 없다. 03은 같은 순서에 속한 모든 차량의 관측점을 지도에 표시할 수 있게 한다. 전체 800개 파일·20지점을 입력으로 유지하며, A의 한 차량이나 지점별 한 차량을 전체 자료의 대표로 삼지 않는다.

01 요약에는 모든 시각의 영상 좌표가 저장돼 있지 않으므로, 이 단계에서는 원자료의 차량 ID와 영상 좌표를 전체 범위에서 다시 읽는다. 이는 제작팀·관측시간 확인이나 01/02의 재실행이 아니다. 파일별로 나누어 읽고 한 지점 처리가 끝나면 메모리를 해제한다. 실제 분석 실행은 사용자가 한다.

저장할 공간 정보는 화면에 실제 관측점이 있었던 위치의 집합이다. 원본 8000×8000 영상 좌표를 1600×1600 표시 크기에 대응시키며, 같은 화면 점으로 겹친 관측은 한 점으로 표시한다. 이는 **그림을 표시하기 위한 축소**이며, 관측행 수·독립 표본 수·속도·위험도를 추정하는 방법이 아니다. 원래 관측행 수와 제외된 표시점의 이유는 별도로 보존한다.

모든 지점의 전체 관측점 지도와 전체 경로 조회 목록을 먼저 출력한다. 특정 지점·경로 확대는 사용자가 지정할 때만 수행하고, 기본값을 A로 고정하지 않는다. 전체를 읽어 놓고 표시를 위해 특정 경로를 선택하는 것은 분석 표본을 해당 경로로 제한하는 것과 다르다.

### E·R 표시 문제를 고치는 범위

유한한 원래 꼭짓점으로 차로 경계선을 그리되 그림의 화면 밖 부분만 잘리도록 한다. 이미지 밖 꼭짓점 때문에 도형 전체를 버리거나, 꼭짓점을 강제로 화면 끝으로 옮겨 도형 자체를 바꾸지 않는다. 화면 밖 좌표가 있다는 사실과 실제 좌표 오류는 구분하여 기록한다. 원래 지도와 02에 저장된 그림은 수정하지 않고 03의 새 결과 폴더에 저장한다.

### 원논문과의 연결 및 다음 단계의 범위

독립 문헌 검토에서 M1 PDF p.5와 M2 PDF pp.2–3을 재확인했다. M1은 특정 좌회전·직진 흐름의 상호작용을, M2는 접근부 대상 차로의 연속된 차량쌍을 다룬다. 관측점의 공간 분포는 분석할 구역과 흐름을 정하는 데 보조 자료가 된다. **03이 두 논문의 사건 추출 알고리즘을 구현했다는 뜻은 아니다.**

특히 다음 한계를 기록한다.

- 점의 집합만으로는 시간순서, 차량별 진행 방향, 두 차량의 동시성이나 선후 관계를 알 수 없다.
- 같은 구역 순서에 속하더라도 서로 다른 차로와 세부 경로로 움직일 수 있다. 같은 경로 ID를 같은 물리적 궤적 또는 한 사건으로 해석하지 않는다.
- 표시용 픽셀을 TTC/PET 거리 계산이나 정밀한 충돌 공간의 좌표로 사용하지 않는다. 지표 계산은 시간순 차량 궤적과 미터 좌표, 차량 크기로 돌아가야 한다.
- 무라벨·한 구역 기록과 표시할 유효 좌표가 없는 기록을 임의로 분석 대상에서 삭제하지 않는다.
- H의 중복 시각 원인은 이 공간 그림으로 해결되지 않는다. 같은 화면 점을 한 점으로 표시하는 처리도 원자료의 중복 시각 정제와 다르다.

**이번 대조 뒤에 7,228개 순서를 모두 수작업으로 완전한 진입·진출 경로에 분류하는 단계를 필수로 두지 않는다.** 특히 M2 후미추돌 분석의 선행조건으로 그런 절차를 요구할 원문 근거는 없다. 지도 시각화만 반복하지 않고 다음의 사건 구성 명세로 연결한다.

1. 후미추돌의 대상 접근 차로와 순간별 앞뒤 관계, 교차상충의 대상 이동 흐름·공간을 각각 정의한다.
2. 원래 시간축·미터 좌표·차체 기준으로 계산 가능한 기록과 중복·관측 공백 상태를 구분한다.
3. M2의 공통 주행구간 PET와 교차상충 PET를 구분하고 TTC의 속도·충돌 경로 가정을 명시한다. ‘고정 횡단선 하나’로 읽힐 수 있었던 표현은 직접 인용 문헌을 확인한 [11 기록](11_원논문에서차량쌍과사건구성으로.md)에 따라 수정했다.
4. 차량쌍의 어느 연속 상호작용을 한 사건으로 보는지와 사건 대표값을 정한다.
5. 지표가 정의되지 않는 경우와 관측 부족을 구분해 남긴다. 두 지표가 모두 있는 경우만 설명 없이 남기지 않는다.

이 항목의 세부 계산법은 원논문과 인용·보조 문헌에서 근거를 확인해 구체화한다. 새로운 주제나 임의의 시간·각도·거리 기준으로 빈 부분을 채우지 않는다.

사용자가 실행·저장한 뒤에는 20지점 지도와 좌표 품질 기록을 함께 읽는다. 그 확인을 다음 사건 구성 명세로 연결하며, 그림을 보고 임의로 좌·우회전이나 상충을 확정하지 않는다.

### 01·02에서 무엇이 이어졌는가

01은 차량별로 도로·차로 번호가 바뀐 순서를 묶었다. 02는 이를 도로 구역 순서로 정리하고 지도 구역 번호와 연결했다. 03은 그 순서에 속한 차량들이 실제로 관측된 영상 좌표를 읽어, 지점별·경로별로 지도에서 볼 수 있게 했다. 예를 들어 02의 `3_4 → <unlabeled> → 4_3`이라는 목록에 실제 관측 위치를 붙일 수 있게 된 것이다.

800개 입력 파일의 위치를 모두 처리했다. 12번 셀의 ‘추가 확대 생략’은 사용자가 별도 지점을 선택하지 않았다는 뜻이며, 전체 처리를 생략했다는 뜻이 아니다. 전체 20지점 표와 지도는 그 앞에서 이미 저장됐다.

### 빨간 점과 지도 밖 좌표의 의미

빨간 점은 해당 화면 위치에 관측 좌표가 있었다는 표시다. 8000×8000 원영상 좌표를 1600×1600 화면 위치로 바꿨으며 같은 화면 픽셀에 들어오는 관측점은 겹쳐 표시한다. 점을 선으로 연결하거나 관측 사이를 보간하지 않았다. 서로 다른 날짜·시간대의 점이 한 지도에 함께 있으므로, 빨간 경로가 겹쳐도 두 차량이 동시에 만났거나 상충했다는 의미가 아니다. 색과 면적을 교통량·위험도·독립 상충 표본 수로 해석하지 않는다.

`n_outside_rows`는 `Ortho_X`, `Ortho_Y`가 유한하지만 둘 중 하나라도 `[0, 8000)` 밖에 있는 관측행 수다. **도로 밖에 있었다는 판정이 아니라, 표시용 이미지 사각형 밖이라는 뜻**이다. C는 17,893,284행 중 2,209,342행(12.3473%), Q는 23,583,762행 중 533,149행(2.2607%)이 해당한다. 좌표 변환·지도 범위·관측 범위 중 어느 원인인지 이 결과만으로 정하지 않는다. 해당 좌표를 원자료에서 삭제하거나 임의로 이미지 안으로 옮기지 않았다. 후속 대상 공간 정의 때 이 범위의 영향을 구분해야 한다.

C·E·R·Q 개별 PNG를 직접 열어 도로 구역과 빨간 관측점 표시를 확인했다. 이미지 사각형 안의 흰 정사영상 배경에도 점이 있는 부분이 보인다. 이는 위의 ‘이미지 사각형 밖’ 집계와 다른 문제이며, 흰 배경이라는 이유만으로 좌표 오류나 차량 손실을 단정하지 않는다. 20지점 모음 PNG는 1600×2000 RGB로 정상 디코드된다. 이번 확인을 모든 개별 지도의 모든 경로에 대한 의미 해석 완료로 확대하지 않는다.

E·R의 꼭짓점 일부가 이미지 밖인 도형도 원래 꼭짓점으로 그리도록 보완됐다. 전체 1,339개 도형의 좌표가 유한하며, 꼭짓점이 모두 이미지 범위 안인 도형은 1,312개다. 원래 27개 도형의 좌표를 수정한 것이 아니라 화면에 걸치는 경계선을 표시한 것이다.

### 저장 결과 독립 검산과 현재 연구 단계

독립 검토에서 NPZ 20개·경로별 배열 7,228개의 자료형, 고유·정렬 상태, 픽셀 범위와 카탈로그 건수를 확인했다. 지점별 CSV와 전체 카탈로그가 모든 열에서 일치한다. 경로별 고유 픽셀 수의 합은 41,349,923개이며, 같은 지점의 경로끼리 겹치는 점까지 합친 지점별 고유 픽셀 수의 합은 8,257,450개다. 두 값은 집계 단위가 달라 정상적으로 다르며 연구의 사건 수가 아니다. 03에 기록된 01·02 제어 파일 8개와 02 차량 요약 800개의 SHA-256은 현재 파일과 모두 일치한다. 확인한 집계·출처 불일치는 없다.

03의 전수 처리 셀에 기록된 `elapsed_s=1046.831`은 약 17분 27초의 컴퓨터 처리시간이다. 촬영시간·관측 노출시간이 아니다. 저장된 03 노트북의 SHA-256은 `5b787348ada5f4fe5543c4bdc8667f627a9c5bd10bf59879e4ddd4e67737f2a8`이다. 실행 출력이 추가됐으므로 실행 전 노트북 해시와 달라지는 것은 정상이다.

이번에 완료한 것은 전체 자료의 **관측 위치와 지도 구역 연결**이다. M1의 교차 흐름, M2의 같은 접근 차로 앞뒤 차량을 정할 때 사용할 공간 자료가 마련됐다. 시간·진행 방향·동시성·차체 정보를 사용한 차량쌍 사건 구성과 TTC/PET 계산은 아직 수행하지 않았다. 다음에는 대상 접근 차로·이동 흐름에 시간순 차량 관계를 결합하는 사건 명세를 원논문과 필요한 보조 문헌에 맞춰 구체화한다. 관측점 지도만으로 상충유형이나 EVT 연구 결과를 확정하지 않는다.
